# Decisions

- 2026-10-16: Python is pinned to `>=3.12,<3.13` and the build backend is hatchling, the simplest layout for a `src/` package.
- 2026-10-16: `mypy --strict` runs on `node/src` and `node/tests` (the whole of `node/` minus the virtualenv), from `node/`.
- 2026-10-16: ESLint uses the flat config with `@eslint/js` and `typescript-eslint` recommended rules; `tsc` covers `worker/src` and `worker/tests`.
- 2026-10-16: the `contracts` check passes with a message while `scripts/contracts.sh` does not exist.
- 2026-10-16: the generator is the stdlib-only `scripts/contracts_gen.py` (run by `contracts.sh` with `uv run --no-project`) rather than a third-party tool; it handles only the JSON Schema subset the contracts use, and lint covers it with ruff and mypy.
- 2026-10-16: generated Pydantic models forbid extra fields and validate in strict mode; the logger converts the event to the generated `LogEventName` itself, and rejects `ts` and `service`, which it sets. Fields of the log line other than those are `request_id`, `video_id`, `attrs`, `level`.
- 2026-10-16: the log schema does not tie each event to its service or its `attrs` keys (the spec's tables are documentation); TypeScript has no generated runtime validator, so worker tests validate against the schema files with `ajv` (dev dependency), and `log.ts` checks event, field names and level at runtime.
- 2026-10-16: optional log fields (`request_id`, `video_id`) are typed non-null like the schema; the Python models default them to `None` only to mean "absent", and the logger writes with `exclude_unset` so the key is left out; the generator is run with `--python 3.12`.
- 2026-10-16: the catalogue is generated in TypeScript as a `LOG_EVENT_NAMES` const array with the `LogEventName` union derived from it, so `log.ts` can check names at runtime.
- 2026-10-16: VTT code lives in `yt_digest_node/vtt.py`; `clean_cues` takes segments as `(start, end)` float tuples and returns the paragraphs as a list of strings (joining with `\n\n` is left to the caller).
- 2026-10-16: for the 2.0 s gap, a "kept cue" is a cue outside the sponsor segments that still has at least one line after step 4; the gap is measured from the end of the previous such cue.
- 2026-10-16: tags are removed with the single pattern `<[^>]*>` (which covers every tag kind of step 3) before entities are decoded, so a decoded `&lt;` survives; bracketed annotations do not span lines.
- 2026-10-16: the 2.0 s gap is compared in whole milliseconds (VTT times are millisecond-exact), so float error never hides a gap; a cue whose lines are all rolling duplicates is not a kept cue, which is the reading of step 5 we keep.
- 2026-10-16: the SponsorBlock client uses stdlib `urllib` (`fetch_segments(base_url, video_id, request_id)` returns the segments and `ok`/`none`/`error`); a 200 whose body is not the expected JSON counts as `error` with no segments, and the `sponsorblock.call` line is `info` for `ok`/`none` and `warn` for `error`.
- 2026-10-16: `sponsor_ratio(segments, duration)` returns 0 when the duration is not positive; the cue cut of step 2 is the existing `clean_cues` midpoint rule.
- 2026-10-16: the SponsorBlock 10 s timeout is the `urllib` socket timeout (applied to each blocking socket operation), not a deadline for the whole call; redirects are followed silently by `urllib`; a segment with a non-finite bound counts as a malformed body (`error`); any `http.client.HTTPException` (truncated or garbage response) counts as a network error.
- 2026-10-16: `yt-dlp` is a runtime dependency; the extractor takes the yt-dlp module, the sleep function and the delay range as parameters so tests use a stub, and the fake extractor path never sleeps (the delay applies only to `YtDlpExtractor`).
- 2026-10-16: a missing or null yt-dlp `duration` (live streams, premieres) becomes 0, so `sponsor_ratio` is 0; the yt-dlp options also set `quiet` and `no_warnings` to keep yt-dlp off stdout/stderr.
- 2026-10-16: `choose_track` returns `None` when no track matches, and the caller reads `None` as `no_transcript`.
- 2026-10-16: an extractor takes the language order (`extract(video_id, langs)`); the yt-dlp extractor calls `extract_info(download=False)`, picks the track itself (manual then auto, in language order, exact language match, only entries with a `vtt` format) and downloads only that one through `ydl.urlopen`, with the random delay before the metadata request and before that download; the fake extractor ignores the languages and returns every file.
- 2026-10-16: among `automatic_captions`, when a `<lang>-orig` key exists only the `-orig` tracks are considered (with the suffix removed), because yt-dlp lists machine translations under plain keys; otherwise all auto keys are considered.
- 2026-10-16: a yt-dlp `DownloadError` whose message contains "not a bot" is `blocked`, any other `DownloadError` is `unavailable`; other exceptions (including networking errors while downloading the track) propagate. Subtitle bytes are decoded as UTF-8 with replacement characters.
- 2026-10-16: truncation and pagination work on the paragraph list of `clean_cues`; the `[…]` marker is its own paragraph and counts as zero words, so it never opens a page by itself and is left out of `word_count`.
- 2026-10-16: a paragraph longer than `PAGE_WORDS` closes the current page and is cut into full pages; its last piece stays open for the next paragraphs.
- 2026-10-16: the command is `yt-digest-node` (a `[project.scripts]` entry) and also `python -m yt_digest_node`; an invalid `MAX_WORDS`, `PAGE_WORDS`, empty language list or missing `FAKE_YTDLP_DIR` exits 2 with a message on standard error and no result.
- 2026-10-16: SponsorBlock is called only when a track was chosen; on other statuses `fetch.transcript` carries `sponsorblock: "none"`, `source` and `sponsor_ratio` null, and `words` and `pages` 0. `service.started` is logged once the arguments are valid.
- 2026-10-18: `transcript` in `node-result-request` is `anyOf` a `$ref` to `transcript-result.schema.json` and `null`; the generator resolves a `$ref` (alone or in such an `anyOf`) to an import of the generated type, and the `$ref` is a relative file name.
- 2026-10-18: an object nested in a property (or in array items) carries a `title` and is generated as its own class or interface (`ClaimedJob`, `ErrorBody`) in the file of its parent schema; `minLength` and `maxLength` are supported by the generator.
- 2026-10-18: the timestamp pattern of the log `ts` field is reused for every timestamp of the node protocol; the contracts keep optional fields absent-or-valid, with `null` only where the spec says so.
- 2026-10-18: worker tests run with `@cloudflare/vitest-pool-workers` in a second Vitest project (`worker`, `worker/tests/worker/`) next to the plain `node` project that keeps the lot 1 tests; vitest is pinned to `^4.1.0` (the pool's peer range) and the packages are installed with `--legacy-peer-deps` because npm 10 crashes resolving that peer set; migrations are applied by a setup file.
- 2026-10-18: `wrangler.toml` carries a placeholder all-zero `database_id` (needed by wrangler even locally, no account id); the ops token is compared by SHA-256 digests of both values in a XOR loop; `/ops/*` with a valid bearer and an unlisted route or method gives 404 `not_found`.
- 2026-10-18: all tables are created by one migration `0001_init.sql`, with `NOT NULL` only on columns the spec always fills; `/ops/reset` leaves R2 objects outside `transcripts/` alone.
- 2026-10-18: `export const name` was removed from `worker/src/index.ts` (and its placeholder test): workerd refuses a Worker module that exports anything but handlers, so `wrangler dev` could not start.
- 2026-10-18: `stack.sh` records the process-group ids (from `setsid`) in `.stack/pids`; `down` sends TERM, waits up to 10 s for the groups to hold only zombies, then KILL; a port counts as taken when a TCP connect to it succeeds; `up` also fails early when one of its processes exits.
- 2026-10-18: Playwright projects are told apart by file name (`*.api.spec.ts`, `*.browser.spec.ts`) in `e2e/tests/`; the mocks server answers 404 `Not Found` to every unknown route.
- 2026-10-18: `e2e.sh` decides that Chromium is unavailable when the bounded `playwright install` exits non-zero; ports are read by the tests from `WORKER_PORT` and `MOCKS_PORT`.
- 2026-10-18: the Worker validates `/node/*` bodies with hand-written checks of the two schemas (heartbeat, claim) because workerd forbids the code generation Ajv needs; the Ajv-based tests still pin the schemas.
- 2026-10-18: a claim is one D1 batch: a conditional `UPDATE … WHERE status = 'queued' AND rowid IN (SELECT … ORDER BY … LIMIT)`, an `INSERT … SELECT` of the `leases` rows, and a `SELECT` of the claimed jobs; the lease id is a random 32-hex claim prefix, a dot and the video id, which identifies the claim's rows and is unique.
- 2026-10-18: `POST /ops/jobs` creates jobs with `INSERT OR IGNORE` (changes tell new from existing) then raises the priority with `max()`; jobs created by one request share a `created_at`, so their claim order is by `video_id`. It logs one `job.enqueued` per request (no `video_id`), with the count of new jobs.
- 2026-10-18: `auth.bearer.rejected` is also logged for `/ops` (`missing` without a bearer, `unknown` otherwise); an unknown `/node/*` route or method is checked before authentication and gives 404 `not_found` (so `/node/result` without a token is 404, not 401, until the next ticket adds it); a malformed body is checked after authentication.
- 2026-10-18: a video id repeated in one `POST /ops/jobs` request is deduplicated (first occurrence kept), so it appears once in `enqueued` or `existing`.
- 2026-10-18: the expiry sweep (8.6) comes with the next ticket, so claims and `GET /ops/jobs/<video_id>` do not run it yet.
- 2026-10-18: the Worker log writes each event with `console.log` (workerd has no `process`), which wrangler sends to its output and so to `.stack/logs/worker.log`.
- 2026-10-18: a retried `POST /node/claim` is a new claim (the claim schema has no idempotency key), so a lost response leaves leases that only the expiry sweep of the next ticket recovers; heartbeats are idempotent.
- 2026-10-18: `LEASE_SECONDS` is used when it is a positive number (fractions allowed); any other value silently falls back to 600.
- 2026-10-18: the `/ops/nodes` and `/ops/jobs` bodies reject unknown keys with 400; a `priority` must be a non-negative safe integer (above 2^53 - 1 gives 400, not a D1 bind failure).
- 2026-10-18: the Worker validates the `/node/result` and `/node/release` bodies with hand-written checks of their schemas (as for heartbeat and claim); the expiry sweep runs after validation on every `/node/*` request and in `GET /ops/jobs/<video_id>`, replacing the earlier "next ticket" note.
- 2026-10-18: ending a lease (result, expiry, validation failure, revocation) is one D1 batch: an `UPDATE jobs … WHERE status = 'leased' AND lease_id = ?`, an `UPDATE leases … WHERE state = 'active' AND changes() > 0` that also stores `response_json`, and the node event insert guarded by `changes() > 0`; only the caller whose lease update changed a row wins, the other answers from the stored state (`completed` gives its stored response, anything else 409).
- 2026-10-18: a job that becomes `done` or goes through the failure handling gets `leased_by`, `lease_id` and `lease_expires_at` set to null; the node that produced a transcript is kept in the R2 metadata and `tried_nodes`.
- 2026-10-18: the validation failure `reason` is one of `transcript_missing`, `transcript_not_null`, `status_mismatch`, `video_id_mismatch`, `pages_empty`, `word_count_mismatch`; the words counted for `word_count` are the whitespace-separated tokens of all pages except tokens equal to `[…]`.
- 2026-10-18: the R2 object is stored as `JSON.stringify` of the validated transcript; the write is a conditional put (`onlyIf: { etagDoesNotMatch: "*" }`) so an existing object is never overwritten even by concurrent retries; an R2 write that throws gives 503 `storage_error`.
- 2026-10-18: a release and a revocation record no node event (6.3 has no kind for them); `job.stale_result` carries the `video_id` only when the lease is known; revoking a node again returns the same 200 with no log; `DELETE /ops/nodes` revokes without running the expiry sweep first.
- 2026-10-18: Worker tests control the Worker's clock with Vitest fake timers on `Date` only; the e2e tests rely on `LEASE_SECONDS=5` set by the `e2e` check (a margin for slow runners).
- 2026-10-18: a claim only leases jobs while its node is not revoked (the claim `UPDATE` checks `nodes.revoked_at` in the same statement), so a revocation sees every lease a concurrent claim creates; a result's lease end also requires `lease_expires_at` to be after the Worker's clock at the write.
- 2026-10-18: an `ok` result first reserves its lease with a conditional UPDATE (`active` to `storing`, unexpired, node not revoked); only that request writes to R2, then ends the lease from `storing`. The sweep and the revocation skip `storing` leases (a revocation landing meanwhile does not revoke it), a failed put returns the lease to `active`, and a `storing` lease older than 60 s past its expiry is swept as expired.
- 2026-10-18: a release requires the lease to be unexpired at write time; otherwise the sweep ends it as `expired` and the answer is 409. A repeated `DELETE /ops/nodes` still ends the node's remaining active leases.
- 2026-10-18: the node daemon uses only the standard library (`urllib`); a missing `WORKER_URL` or `NODE_TOKEN`, or an invalid `CLAIM_BATCH`, `POLL_SECONDS` or `HEARTBEAT_SECONDS`, prints one plain line on standard error (as lot 1 does for a bad argument) and exits 2 before any log line or request.
- 2026-10-18: in the loop, a network error or non-2xx other than 401 on a heartbeat or claim is not fatal (the cycle waits `POLL_SECONDS` and starts again); a result or release that fails for good (4xx, retries exhausted) is dropped and the lease expiry recovers the job; the heartbeat is also sent between the jobs of a batch when due, with `jobs_in_progress` the jobs of the batch not yet finished.
- 2026-10-18: each HTTP attempt, retries included, logs one `worker.call`, with the `video_id` for `result` and `release`.
- 2026-10-18: the mocks server's `authorize` only requires `redirect_uri` to be present (any value is accepted and echoed in the redirect); the token endpoint requires the same `redirect_uri` for the code, and a code is consumed by its first exchange attempt even if it fails; a refresh grant returns no new `refresh_token` and no `nonce`; the `kid` is the first 16 hexadecimal characters of the SHA-256 of the public JWK; revoke ignores its body and answers `{}`; the mocks server computes its issuer from `MOCKS_PORT`.
- 2026-10-18: `POST /ops/invites` and `/ops/invites/revoke` reject unknown body keys with 400 and write no log line; the e-mail is lowercased only (not trimmed).
- 2026-10-18: `PUBLIC_URL` falls back to the request's origin when unset; the Google client id, secret, admin e-mail and `TOKEN_ENC_KEY` fall back to the defaults of 5.2; a missing `GOOGLE_ISSUER` makes a consent `approve` fail with a 500 (nothing is bound, so it can be retried), and the callback answer a `server_error` redirect.
- 2026-10-18: `POST /register` answers 400 `invalid_request` (6.1) for a body that is not parseable JSON or not a JSON object; more than 10 redirect URIs is `invalid_redirect_uri`; `grant_types` may be any subset (even empty) and the answer always lists both grant types.
- 2026-10-18: an `/authorize` scope is valid when it is non-empty and every space-separated word is `digest`; the stored scope is `digest`.
- 2026-10-18: a consent `approve` binds the Google state and nonce to the pending authorization and only works once (a second approve gives 400); the callback is what uses the pending authorization up; an unknown `decision` or a body that is not a form gives 400 HTML without using the request.
- 2026-10-18: the `auth.oauth.denied` reason is `access_denied` for a consent `deny`, and `google_error` for an `error` parameter from Google and for any failure of the code exchange or ID token checks; `not_invited` and `email_unverified` come with the 403 page.
- 2026-10-18: an unverified e-mail is refused even for the admin; a login without a Google refresh token keeps the one already stored for the user.
- 2026-10-18: the Google discovery document is fetched at each `approve` and each callback, not cached.
- 2026-10-18: the callback's access control is part of its writes: the `users` upsert and the `oauth_codes` insert each select `WHERE` the user is the admin or has an unrevoked invite, in one batch, and the 403 page is chosen when the code insert changed no row.
